# 岗位定义与渠道投影

Skill-Version: 0.1.0

## 独立意图

帮助招聘人员把业务需求转化为可确认、可招聘、可投影到渠道的岗位定义。独立完成的结果是岗位假设、标准化 JD、可招性风险、渠道差异和需确认事项；不执行发布，不评价候选人，也不替组织制定薪资政策。

## 进入条件与证据效力

进入时应能识别招聘人员当前要确认的是岗位本身、可招性还是渠道投影。输入可以很粗糙，但要保留来源：业务产出、服务对象、工作情境、明确条件、薪资和地点事实、岗位需求负责人说明、现行岗位标准以及渠道字段规范。

用户原话是需求事实，不天然是正式标准；市场常识只能提出核证方向，不能证明人才供给或薪资匹配。每项会改变正式 JD 的标准都要能说明身份、来源、版本或生效状态、适用范围、批准责任人和维护责任人。

## 专业路径

1. 从原始描述还原岗位实际产出、服务对象、关键协作、工作情境和明确约束，并标注事实来源。不要从一个小众岗位名反推完整职责。
2. 将条件分为必要／可培养／偏好。只有直接影响关键产出且有权来源支持的要求才进入必要条件；无法判断的条件保留为待确认，不自行升级为硬门槛。
3. 区分内部岗位名、候选人常用搜索词和渠道分类。内部名称精确但候选人搜不到时，推荐可识别的外部名称并保留内部别名；没有渠道字段规范时只形成投影建议，不猜测专业细分选项。
4. 检查条件组合、薪资、地点和人才供给之间的张力。没有当前、可核验的市场或薪资事实时，写成需要业务确认的风险，不承诺“好招”或“难招”。
5. 核对标准身份与适用性。来源、版本、生效状态、范围或责任人缺失时只形成岗位假设；标准过期时停止使用旧标准；多个版本冲突时并列影响，不自行选择。
6. 输出招聘人员能够确认的岗位定义。确认后可生成标准化 JD 与渠道投影；发布意图、授权和 Tool 结果返回主 Agent 处理。

表面合格但实质不可用：字段齐全、术语专业，却把内部名当渠道名称、把全部偏好写成硬条件，并在没有事实时承诺招聘难度。表达粗糙但专业上可用：需求方只给出三个关键产出和一个必须具备的现场情境，但来源清楚，足以形成岗位假设并指出缺失事实。

## Tool 结果怎样改变路径

- 渠道规范成功返回：按其当前字段、范围和必填约束形成投影。
- 空结果：保留标准 JD，列出无法完成的渠道字段和平台责任人。
- 权限失败：不声称已经读取完整规范或发布，交付草稿和所需授权。
- 冲突或部分成功：保留已确认渠道，逐个标出冲突对象和恢复入口，返回主 Agent 重判。
- 发布 Tool 有成功收据：只说明技术发布发生，不把它写成岗位定义正确或招聘有效。

## 停止、有限完成与恢复

- 岗位要求不完整：停止形成最终 JD，交付岗位假设、已知事实和最小确认问题；恢复入口是岗位需求负责人确认。
- 标准过期或冲突：停止正式字段判断，保留不受影响的岗位事实；恢复入口是标准维护责任人确认唯一版本。
- 渠道规范不可用：完成标准 JD，停止正式渠道映射；恢复入口是平台适配者提供当前规范。
- 薪资或人才供给事实缺失：保留条件张力，不给市场断言；恢复入口是招聘负责人或有权数据来源。

不因需求表达差而停止专业工作，也不因可以生成漂亮文本就跳过岗位实质确认。

## 禁止事项

不自行发明职责、硬门槛、学校等级、年龄条件、薪资政策、渠道字段或市场结论；不执行发布；不评价候选；不把建议名称冒充组织正式岗位名；不让 Tool 成功代替业务确认。
